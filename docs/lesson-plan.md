# 实训课设计：用 Dify 搭建"课程答疑助手"

- 适用课程：人工智能技术应用 / 大数据技术专业，《大模型应用开发》或《AI 应用实践》
- 对象：高职二年级（已学过 Python 基础）
- 学时：4 学时（2 次课，每次 2 学时）
- 环境：教师机或机房服务器部署 Dify（Docker），学生用浏览器访问；每组一个工作区

## 学习目标

学完后学生能够：
1. 说出"检索增强生成（RAG）"的三个步骤：切分文档、检索相关片段、带着片段让大模型回答。
2. 在 Dify 中创建知识库，并解释分块方式对回答质量的影响。
3. 搭建一个"检索 → 大模型 → 输出"的对话工作流，并写出带规则的提示词。
4. 设计 5 道测试题检验自己的助手，记录哪些答对、哪些答错、为什么。

## 第 1 次课（2 学时）：知识库与分块

| 时间 | 活动 | 说明 |
|---|---|---|
| 15 分钟 | 导入演示 | 教师演示现成的"课程答疑助手"：问讲义里有的、讲义里没有的、实验题怎么做，让学生观察三种不同的回答。 |
| 15 分钟 | 讲解 RAG | 用一张图讲"切分 → 检索 → 回答"；强调大模型只看到被检索到的片段。 |
| 40 分钟 | 实操 1：建知识库 | 学生上传给定讲义（`python_lecture04_lists_loops.md`），分别用"按行切分"和"按标题 `\n## ` 切分"各建一次，在"检索测试"中输入同一个问题，比较命中的片段。 |
| 20 分钟 | 小组讨论 | 为什么按行切分后代码示例会被拆碎？什么样的文档适合按标题切？ |

## 第 2 次课（2 学时）：工作流、提示词与测试

| 时间 | 活动 | 说明 |
|---|---|---|
| 30 分钟 | 实操 2：搭工作流 | 新建 Chatflow：开始 → 知识检索 → LLM → 直接回复。把知识检索结果设为 LLM 的上下文。 |
| 30 分钟 | 实操 3：写提示词 | 至少包含三条规则：只根据讲义回答；讲义没有的要说明；回答后标注小节出处。 |
| 30 分钟 | 实操 4：测试 | 每组设计 5 道测试题（至少 1 道讲义外的题、1 道"直接给我答案"的题），填写下面的测试记录表。 |
| 10 分钟 | 展示与点评 | 每组展示一道答错的题，说明原因和改法。 |

## 评分（100 分）

| 项目 | 分值 | 标准 |
|---|---|---|
| 知识库 | 20 | 能说明选用的分块方式及理由，检索测试截图能命中正确小节 |
| 工作流 | 20 | 工作流能正常运行，上下文正确连接 |
| 提示词 | 20 | 三条规则齐全，并在测试中起作用 |
| 测试记录 | 30 | 5 道题设计合理，至少有一道失败案例并分析原因 |
| 展示 | 10 | 表达清楚，能回答教师追问 |

## 与技能竞赛的衔接

职业院校技能大赛中与人工智能应用相关的赛项通常考查数据处理、模型应用和应用部署。本实训覆盖其中"应用搭建 + 测试验证"的部分；参赛学生可以在此基础上增加：
- 用 HTTP 节点调用自己写的 Python 接口（参考本项目的规则服务）；
- 用评测脚本批量测试，统计准确率；
- 比较不同分块参数、不同 Top K 对准确率的影响，写成简短的实验报告。

（具体赛项名称和考核内容以当年发布的赛项规程为准。）

## 教师准备清单

- [ ] Dify 已部署，并配置好模型和嵌入模型的 API Key（学生不接触 Key）
- [ ] 为每组创建工作区账号
- [ ] 准备讲义文件和一个参考答案工作流（`dify/course_qa_assistant.yml` 可直接导入）
- [ ] 准备 2–3 道"诱导性"示范题，用于第一次课导入
