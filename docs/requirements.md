# 需求文档：校园报销政策智能助手

> 状态：v0.1（2026-10-13）· 场景为模拟需求，政策文本均为虚构，不代表任何真实学校。

## 1. 背景

财务处每天重复回答大量报销咨询（差旅标准、会议费、所需票据），政策每年修订，教职工常按旧版本准备材料，导致退单和反复沟通。

## 2. 用户

| 角色 | 需求 | 权限 |
|---|---|---|
| 教师 / 行政人员 | 查询报销规则、所需材料、可报金额 | 只能查询公开政策 |
| 财务审核人员 | 查询审核口径、例外条款 | 可查看内部审核细则 |
| 系统管理员 | 上传 / 更新政策版本，查看审计日志 | 管理权限 |

## 3. 范围

在范围内：

- 基于政策原文回答问题，并给出条款出处（文件名、版本、条款号）。
- 按费用发生日期选择当时有效的政策版本。
- 检查报销所需材料是否齐全。
- 计算差旅补助、住宿上限等金额（确定性规则计算，非模型生成）。
- 记录每次问答的审计日志（问题、检索条款、回答、计算过程、用户反馈）。

不在范围内：

- 审批或驳回报销单。
- 连接真实财务系统或处理真实个人数据。

## 4. 硬性规则

1. 不编造规则：政策中没有依据时，必须明确拒答并建议联系财务处。
2. 每个数字都可追溯到具体条款和计算步骤。
3. 金额计算一律由 Python 规则服务完成，大模型只负责理解问题和组织语言。
4. 按角色过滤可见内容，普通用户看不到内部审核细则。
5. 引用的条款必须真正支持回答，否则不输出该回答。

## 5. 验收标准

- 评测集 30–50 题，覆盖：可回答、旧版本陷阱、无依据拒答、越权请求、计算边界、诱导性问题。
- 报告指标：回答准确率、正确拒答率、计算错误率、错误引用率、旧版本错误率。
- 一条命令（`docker compose up`）可复现部署。

## 6. 架构概要

```
用户 → Dify 应用（检索政策 + 工作流）→ 调用规则服务（FastAPI）
                                        ├─ 版本选择 / 权限过滤
                                        ├─ 确定性计算
                                        ├─ 引用校验
                                        └─ PostgreSQL 审计日志
```
